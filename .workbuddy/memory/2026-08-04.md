## 回注工具超大文件策略评估（只评估，未改动）

用户询问 inject.py 对超大 IDML 回注的策略。结论：**无超大文件专门处理，一次性全量内存模型**。

关键事实：
- `extract_from_idml`：Story XML 整体读入 + raw_story_xmls 原始 XML 双份 + 逐字符 8 字段 dict
- `_write_stories_to_idml`：整个 ZIP 全量解压进 all_files dict 再重打包（内存峰值点，约解压后 ×2）
- `_verify_output`：对输出再完整跑一遍 extract_from_idml（解析重复 1-2 次）
- `_should_suppress_punct`：逐句号前/后扫描，最坏 O(n²)
- 无流式 / 无分块 / 无规模阈值分支 / 无进度条 / 无内存监控

历史文件规模：300-500KB（压缩 IDML，3-9 万字），运行正常。百万字级预估峰值 1GB+。

用户决策：**暂不处理，仅了解现状**。后续若接超大文件任务需先压测再定方案（候选：ZIP 按需读写、按 Story 分批、去全量解压）。
